## Objective

## Background: What is SPI?

SPI (Serial Peripheral Interface) is a synchronous serial communication protocol used for short-distance communication, typically between a microcontroller and peripherals or, in our case, between an ESP32 and an FPGA.

### SPI Signals

A standard SPI bus has four signals:

| Signal    | Direction       | Description                                    |
|-----------|-----------------|------------------------------------------------|
| SCLK      | Master → Slave  | Clock signal, generated by the master          |
| MOSI      | Master → Slave  | Master Out Slave In - data from master         |
| MISO      | Slave → Master  | Master In Slave Out - data from slave          |
| SS/CS     | Master → Slave  | Slave Select (or Chip Select) - activates slave|

In our project:
- **SCLK** → FPGA pin 34
- **MOSI** → FPGA pin 33
- **MISO** → FPGA pin 32
- **SS** → FPGA pin 35

### SPI Phases: CPOL and CPHA

SPI has four modes defined by CPOL (Clock Polarity) and CPHA (Clock Phase):

| Mode | CPOL | CPHA | Description                              |
|------|------|------|------------------------------------------|
| 0    | 0    | 0    | Idle low, data on first edge (rising)   |
| 1    | 0    | 1    | Idle low, data on second edge (falling) |
| 2    | 1    | 0    | Idle high, data on first edge (falling) |
| 3    | 1    | 1    | Idle high, data on second edge (rising) |

**Our project uses Mode 0: CPOL=0, CPHA=0**

- **CPOL=0**: Clock is idle LOW when not in use
- **CPHA=0**: Data is sampled on the **first** clock edge (rising edge when CPOL=0)

```
CPOL=0, CPHA=0:

SCLK:   ___ ___ ___ ___ ___
       |   |   |   |   |   |
       |   |   |   |   |   |
MOSI:  | 1 | 0 | 1 | 1 | 0 |  ...  (sampled at rising edges)
       |___|___|___|___|___|
```

### Our Custom 16-Bit Protocol

Instead of using a standard SPI peripheral protocol, we'll use a simplified custom protocol:

- Each SPI transaction transfers **16 bits**
- **Bits 15-8** (first byte sent): Command byte
- **Bits 7-0** (second byte sent): Data direction depends on command
  - For **read** commands: Data is shifted OUT from the FPGA
  - For **write** commands: Data is shifted IN to the FPGA

```
Master sends:  [  COMMAND  ][  DATA (write) / Don't Care (read)  ]
Master receives: [ Don't Care (write) ][  DATA (read)  ]

Timing (16 bits, MSB first):
SCLK:    _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\ _/_\
          |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |
CMD:      | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |   |   |   |
DAT:      |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   |   | X | X |
      |___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|___|
       ↑                                                                 ↑
     SS falls                                                              SS rises
     (transaction starts)                                                 (transaction ends)
```

## Your Task: Create the SPI Target Module

Create a file `spi_educational/rtl/spi_target.v` with the following module:

```verilog
module spi_target(
    input  wire clk,           // Main clock (12 MHz)
    input  wire spi_ss,        // SPI Slave Select (active low)
    input  wire spi_sclk,      // SPI Clock
    input  wire spi_mosi,      // SPI Data In (from master)
    output reg  spi_miso       // SPI Data Out (to master)
);
```

### Module Behavior

1. **Shift Register**: The module contains a 16-bit shift register that shifts in data on rising edges of `spi_sclk` when `spi_ss` is low.

2. **Output Shifting**: The `spi_miso` output shifts out data on **falling edges** of the clock (so the data is stable for the master's rising edge sampling). Alternatively, you can use a clock domain approach - sample on rising edge, output on a delayed edge.

3. **Command Register**: After 16 bits are shifted in, the upper 8 bits (command) are available in a separate register (`cmd_reg`) for downstream modules to decode.

4. **Data Registers**: 
   - `data_in_reg[7:0]` - The lower 8 bits that were shifted in (data from master for write operations)
   - `data_out_reg[7:0]` - The lower 8 bits that were shifted out (data to master for read operations)

5. **Transaction Complete Flag**: A register `tx_complete` that goes high for one clock cycle when a 16-bit transaction is complete.

```verilog
    reg        tx_complete;    // Transaction complete flag

    reg        in_transaction;  // Flag indicating SS is low

    // TODO: Implement the shift register logic
    // TODO: Implement command/data register loading on transaction complete
    // TODO: Implement MISO output shifting

endmodule
```

### Key Implementation Details to Consider

1. **When to shift**: The shift register should only update when `spi_ss` is low AND there's a rising edge on `spi_sclk`.

2. **Bit ordering**: Data is shifted in **MSB first**. The first bit received is bit 15 (command bit 7).

3. **MISO timing**: For CPHA=0, the master samples on the rising edge. Your MISO output should be stable before this edge. A common approach is to:
   - Shift in data on rising edge of sclk
   - Shift out data on the same edge but use the value from before the shift

4. **Transaction detection**: Detect when 16 bits have been shifted in, then capture the command and data.

5. **Reset**: Consider adding a synchronous or asynchronous reset input for testing purposes.
