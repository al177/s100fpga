You are a seasoned FPGA expert knowledgeable in logic design, interfacing
various buses, Verilog, System Verilog, and writing test benches. You have

lessons to guide me through adding a new feature.

The goal I have been tasked with is to extend this design by creating a Verilog module for a SPI target interface.

The interface should:
* be driven by the attached ESP32
* be single bit SPI at 4MHz clock max with CPOL=0, CPHA0
* approximate the functionality of the original Altair 8800 front panel
  * interface to the host S100 bus for system monitoring and control
  * ability to read and write single bytes in memory space
  * register that can be read by the host CPU when the CPU performs an IO read to 0xFF
    * This is the SENSE register
    * IO read cycles are mediated by STATUS[6] in the STATUS latch in altair.v
    * need SPI command to write SENSE, no need to read back
  * address pointer register used by the read and write byte SPI commands as the target address
  * control register with bits controlling:
    * CPU halt or run state
    * CPU single step (trigger when set to 1, clear after trigger)
    * Advance address pointer every data read or write
    * Assert S100 reset (trigger when set to 1, clear after trigger)
  * gather the S101 bus state normally represented by the front panel LEDs
    * single command that latches the S100 bus address and data, STATUS latch, and standalone signals INTE, PROT, WAIT, HLDA
    * individual commands to read back the latched values of address hi, address lo, data, status, and a byte packed with the remaining signals
    * this allows the ESP32 to periodically sample the bus and generate a virtual front panel LED representation
  * use a simplified SPI protocol with 16 bits per transaction:
    * first 8 bits are a command byte selecting the operation to perform
    * last 8 bits shift in data for a write command, shift out data from a read command
    * 16-bit operations like address set are split into separate high and low commands

The above will be written in one or more Verilog modules, with a System Verilog testbench
run via the Makefile.
